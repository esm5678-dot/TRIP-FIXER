## 3. 역할과 운영 인계

승민은 **제품 판단 → 모델 선택 → 기능 한 건 지시 → 직접 실행 → 변경 검토 → 커밋**을 반복한다. 팀원의 영어 강점은 자연어 예문, 버튼 문구, 직원용 문장의 영문 뜻을 확인하는 데 쓴다. 기술 검토자는 허용된 범위에서 잘못된 입력, 시간 경계, 키 노출, 인계 방법을 확인한다. 실물 계정의 비밀번호나 API 키를 검토자에게 전달할 이유는 없다.

| 인수 항목 | 전달할 내용 | 받는 사람이 직접 할 일 |
|---|---|---|
| 재현 가능한 버전 | 본선 저장소, 커밋 SHA, Node·패키지 버전과 잠금파일, 설치·시험·배포 매뉴얼 | 빈 환경에서 설치하고 같은 두 결과를 확인 |
| 서비스 설정 | 서버 환경변수 이름, 모델 선택과 해석 범위, 키 교체·재배포·이전 배포 복구 절차, 최종 프롬프트 | 재단 소유 계정에서 새 키 설정. 키가 없을 때 목표 버튼으로 진행한 뒤 키 교체까지 시험 |
| 데이터 | 카드별 출처·확인일·층·입장 마감·접근 조건과 검토 담당 역할, 임시 통제 확인 경로 | 시설 변경 시 카드와 규칙을 함께 수정하고 경계 시험 재실행 |
| 비용 | 호스팅 플랜, 모델별 가격 확인일, 실호출 입력·출력 토큰과 건수, 예산 알림·수동 차단 위치 | 실제 사용량으로 비용 계산. 메모 1회 비용은 입력 토큰 비용과 출력 토큰 비용의 합. 버튼 규칙에는 모델 호출이 발생하지 않음 |
| 권리와 배포물 | 본선 소스·시스템 프롬프트·운영 매뉴얼·실사용 제3자 고지·본선 SBOM·검수 결과 | 의존성·사진·데이터의 재사용 조건과 계정 소유자 확인. 인수 약정과 산출물 목록 대조 |

활동표의 유지보수는 장소마다 다르다. 하이커 2층 무대와 전시층 영업은 한국관광공사 안내, 3층 포토존은 서울시 현장 기록과 최신 시설 안내, 광교 계단은 서울시설공단 진입로와 당일 통제 공지를 대조한다. 주간 정기 검토와 운영 변경 공지 시 즉시 재검토를 운영안으로 제안한다. 카드 근거가 사라지면 해당 후보를 내려두고 마지막 검토일과 이유를 남긴다. 사용자의 대기 보고는 해당 탭의 개인 관측이며 시설 전체 공지가 될 수 없다. ## 4. 3분 발표 안의 1분 시연

| 경과 | 실제 조작과 발표 |
|---|---|
| 0~10초 | 14:50 고정 데모를 연다. “친구와 사진을 찍고 싶은 여행자는 15:30까지 하이커 정문에 돌아와야 합니다.” |
| 10~25초 | 2층에서 Long wait → 45 min을 누른다. “줄만 서도 15:35입니다. 3층에서도 함께 사진을 찍을 수 있어, 그곳이 가능한지 먼저 확인합니다.” |
| 25~35초 | Ask staff를 눌러 3층 직원에게 보여줄 문장을 연다. “3층 대기와 복귀 동선은 아직 모릅니다.” |
| 35~50초 | 직전 변경 취소 → 목표 수정 → K-pop 무대 영상 필수로 설정한다. 다시 같은 45분을 입력한다. |
| 50~60초 | 후보 없음과 복귀 선택을 보여준다. “이 여행자는 무대 촬영이 목적이어서 포토존으로 보내지 않습니다. 목표를 바꿀 권한은 여행자에게 있습니다.” |

남은 2분은 ① 관광객의 문제와 두 목표의 차이, ② AI가 읽는 정보와 코드가 지키는 시간 조건, ③ 운영자가 장소와 근거를 갱신하는 방법에 나눈다. 심사위원이 “오늘 3층은 정말 비었나요?”라고 물으면 당일 대기는 관측하지 않았으며, 현장 확인을 요청하는 후보라고 답한다.
