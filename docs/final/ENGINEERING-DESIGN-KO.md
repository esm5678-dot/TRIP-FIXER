# TRIP FIXER 기술 설계 및 검수 기준

2026년 11월 26일 · 트랙 1 · 리허설 구현 대조본

서울에서 일정이 틀어진 외국인 여행자가 **경험의 목적과 다음 약속을 유지하면서 할 수 있는 행동 하나**를 고른다. 기술 검수자는 사용자가 바꾸지 않은 조건이 보존됐는지, 후보를 낸 이유와 아직 모르는 사항이 화면에 드러나는지 확인한다. 이 문서는 현장 개발 전 검토 기록이다. [대조한 구현 커밋](https://github.com/esm5678-dot/TRIP-FIXER/tree/4caabaab944bc4a86e1445e566e282e2e3a41f76) · [시스템 설계 초안](https://github.com/esm5678-dot/TRIP-FIXER/blob/main/docs/SYSTEM-DESIGN-KO.md)

## 1. 범위와 판정 결과

| 반드시 제공할 기능 | 사용자가 얻는 결과 |
|---|---|
| 목표·시각·동선 확인 | 함께 사진, K-pop 무대 영상, 청계천 산책 중 고른 목적과 서울 당일의 복귀 약속이 고정된다. 사진의 경우 K-pop 배경 선호를 따로 정한다. |
| 현장 변화에 따른 재계산 | 대기·체험 중단·시설 전체 휴관·건너뛰기를 해당 범위에 적용한다. 결과는 다음 행동 하나, 직원에게 보여 줄 한국어 문장, 또는 복귀 안내다. |
| 확인 근거와 재수정 | 운영 자료와 본인의 시간 보고를 구별해 보고, 최신 대기를 고치거나 마지막 현장 변경을 한 번 되돌릴 수 있다. |

활동은 세 개, 출발·복귀 지점은 네 곳이다. 사용자가 직접 고른 지점으로 계산한다. 서울 전역 장소 검색, 실시간 혼잡 수집, 예약, GPS, 중앙 사용자 계정은 범위에서 제외한다. 결과 판정은 세 종류다.

- **조건에 맞음**은 사용자가 현장 이용 가능 여부를 확인했고, 가는 시간·대기·체험·돌아오는 시간을 모두 입력했으며, 입력값으로 계산한 복귀가 마감 이내일 때 표시한다. 이동과 복귀 시간은 사용자 추정이다.
- **현장 확인**은 필수 조건에 명백히 어긋나는 사실이 없지만 이용 가능 여부·시간·동선 접근성 중 확인할 값이 남았을 때 표시한다. 한국어 질문을 바로 열 수 있다.
- **후보 제외**는 해당 카드가 조건을 만족할 수 없는 경우다. 같은 목적의 다른 활동을 확인하고 모두 제외되면 이유, 복귀 장소 지도 검색, 목표 수정 동작을 제공한다. 지도는 정문·층까지의 길이나 도착 예정 시각을 계산하지 않는다.

## 2. 사용자 상태와 화면 동작

| 상태 | 사용자의 입력 | 화면과 서버가 함께 보장할 일 |
|---|---|---|
| 목표 선택 | 목표, 선호, 출발지, 복귀 지점, 30·60·90분 또는 시각, 무계단 조건 | 시작 버튼을 누르면 절대 마감 시각을 산출한다. 자정을 넘기는 상대시간은 오늘의 시각을 다시 고르도록 안내한다. |
| 선택형 영어 입력 | 자기 문장 → Read my note → 제안 확인 | 메모 읽기는 명시적 클릭으로만 실행한다. 제안 수락 후에도 폼을 편집할 수 있다. 모호한 답·장애 시 버튼 선택을 제공한다. |
| 결과 카드 | Ask staff, Long wait, Skip this activity, Closed | 직원 질문은 한국어 원문과 영어 뜻을 연다. 대기는 시간 선택까지 두 번, 건너뛰기는 한 번이다. 휴관은 체험 또는 건물·구역의 범위를 정한다. |
| 시간 확인 | 네 구간 분 단위 입력, 이용 가능 확인, 필요 시 전체 동선 무계단 확인 | 네 값으로 예상 복귀를 계산한다. 체험은 최소 1분, 다른 구간은 직접 입력한 0분도 허용한다. |
| 재평가·편집 | My timing reports, Undo last change, Edit plan | 새 대기는 같은 활동의 이전 대기·확인값을 교체한다. 출발·복귀 지점을 바꾸면 이전 동선의 네 구간 확인값을 폐기한다. 되돌리기는 현재 시각·현행 규칙으로 재계산한다. |
| 후보 없음·종료 | 복귀 장소 찾기, 목표 수정, End trip | 마지막 약속을 계속 표시한다. 종료는 해당 탭의 여행 기록을 지운다. 새로고침하면 확정 계획과 보고가 복원되고, 되돌리기 이력은 끝난다. |

일반 모드는 화면이 다시 보이거나 표시 상태에서 1분이 지날 때 갱신한다. 편집·요청 중에는 자동 평가를 쉬고, 더 오래된 요청의 결과는 최신 선택을 덮어쓰지 못하게 한다. 네트워크 장애 시 요청 재시도를 제공한다. 처음 사용한 사람의 서버 연결과 기존 결과를 가진 사람의 재계산을 구분해 시험한다. 데모 모드는 11월 27일 금요일 14:50 KST에 시계를 고정한다. [화면과 저장 처리](https://github.com/esm5678-dot/TRIP-FIXER/tree/4caabaab944bc4a86e1445e566e282e2e3a41f76/components)

카드 확인일은 2026-11-25다. 하이커 전시층의 화~일 10:00~20:00, 마지막 입장 19:40을 규칙으로 반영했다. 건물 내부 출발과 외부에서 새로 들어가는 경우를 구분한다. 현장 임시 휴관은 사용자가 보고한다. [한국관광공사 시설 운영 안내](https://english.visitkorea.or.kr/svc/whereToGo/locIntrdn/rgnContentsView.do?vcontsId=31124) · [검수한 데이터](https://github.com/esm5678-dot/TRIP-FIXER/blob/4caabaab944bc4a86e1445e566e282e2e3a41f76/data/activities.json)

1. 서버가 서울 날짜·분 단위 시각을 구하고 약속이 지났는지 확인한다. 미래 보고와 이전 서울 날짜의 보고는 평가에서 제외한다.
2. 활동의 허용 목표, 필수 무계단 조건, 시설 전체 휴관, 활동 폐쇄, 해당 여행의 건너뛰기를 검사한다. 이미 내부에 있는지와 공식 입장·종료 시각을 적용한다.
3. 알려진 대기와 보고 시각만으로도 불가능한 경우를 제외한다. 현장 확인값이 오래됐으면 다시 확인한다. 네 구간이 갖춰지면 운영시간과 마감을 모두 비교한다. 새로 확인한 복귀 예상이 마감과 같으면 허용한다. 대기 종료가 마감과 같으면 체험할 시간이 남지 않는다.
4. 남은 후보 중 ‘조건에 맞음’을 먼저 배치하고, 같은 수준이면 사용자가 정한 선호를 반영한다. 동률은 고정된 활동 식별자 순으로 해결한다. 선택 중이던 활동이 탈락하면 그 이유를 결과와 함께 표시한다.

**두 판단을 구별하는 예.** 14:50에 보고한 대기 45분의 가장 빠른 시작은 15:35다. 15:30 정문 약속을 유지하면 2층은 제외한다. 사진 목표는 3층 현장 확인, 무대 필수 목표는 후보 없음이다. 대기가 5분이면 2층을 바로 제외할 근거는 약하지만 이동·체험·복귀 시간을 모르는 한 조건 충족으로 확정할 수도 없다. [판정 함수](https://github.com/esm5678-dot/TRIP-FIXER/blob/4caabaab944bc4a86e1445e566e282e2e3a41f76/lib/recover.ts)

## 4. 서버 계약·데이터 수명·보안

한 웹앱 안에서 브라우저가 요청을 보내고 서버가 입력 검증, 조건 해석 또는 활동 판정을 수행한다. TypeScript의 공통 타입과 Zod의 런타임 검증을 함께 사용한다. 모델 접근 권한은 서버에만 둔다.

| 동작 | 요청의 의미 | 응답의 의미와 장애 처리 |
|---|---|---|
| POST /api/recover · interpret | 300자 이하의 여행자 메모 한 건 | 목표·무대 선호·무계단 필요의 제안, 또는 수동 선택 안내. 시간·URL·장소는 모델 출력 허용 항목에 들어가지 않는다. |
| POST /api/recover · evaluate | 확정 계획, 모드, 개인 보고, 이번 변화, 필요 시 직전 활동 | 마감·남은 시간, 선택된 활동과 상태 또는 빈 결과, 직전 탈락 이유. 잘못된 형식은 400, 과대 본문은 413, 지원하지 않는 전송 형식은 415로 처리한다. |

문장 해석은 서버 환경변수로 모델 하나를 선택한다. 기본값은 gpt-6-luna이며 응답 기한은 5초다. 키 미설정·모델 거절·비정상 구조·시간 초과 시 사용자는 직접 목표를 고른다. 비용은 문장 해석 호출에서 발생한다. 코드에는 키를 기록하지 않고 서버 응답 캐시를 끈다. 메모와 모델 출력에 외부 도구를 실행할 권한이 없다. 모델 제공자에게 보내는 요청의 store 값은 false다. 서비스 계정의 보존 조건과 플랫폼 접근 권한은 별도 인계 대상이다. [입력 검증](https://github.com/esm5678-dot/TRIP-FIXER/blob/4caabaab944bc4a86e1445e566e282e2e3a41f76/lib/contracts.ts) · [요청 처리](https://github.com/esm5678-dot/TRIP-FIXER/blob/4caabaab944bc4a86e1445e566e282e2e3a41f76/app/api/recover/route.ts) · [모델 호출](https://github.com/esm5678-dot/TRIP-FIXER/blob/4caabaab944bc4a86e1445e566e282e2e3a41f76/lib/interpret.ts)

요청 본문은 14,000바이트 이내다. 모델 해석 호출 제한은 서버 인스턴스 하나당 분당 24건이다. 재단 운영 시 전체 인스턴스의 지출은 모델 계정에서 별도로 점검한다. 탭에 저장하는 값은 모드, 목표·약속·동선, 시각이 붙은 개인 보고다. 영어 원문과 GPS는 탭 저장소에 넣지 않는다. 휴관·건너뛰기 보고는 해당 여행에서만 사용하고, 공공 데이터나 다른 여행자의 현황에 합치지 않는다.

## 5. 요구사항과 시험 연결

아래의 ‘확인’은 지정된 소스와 자동 시험의 범위다. 실사용자의 반응과 현장 시설 상태는 별도 증거가 필요하다.

| ID | 사용자가 기대하는 결과 | 근거 코드와 시험 사례 | 검증 경계 |
|---|---|---|---|
| R1 | 필수 목표와 선호를 분리 | recover · strict stage, 45-minute wait / 브라우저 strict goal | 필수 무대와 단체 사진 두 경우의 차이 확인 |
| R2 | 복귀 약속의 시간 보존 | recover · four checked estimates, unknown queue, relative budget, expired day | 추정치 3+4+10+6분의 복귀는 15:13. 실제 보행시간 별도 관측 |
| R3 | 대기·중단의 대상 범위 보존 | recover · activity closure, building-wide closure, new queue / 브라우저 new staff report | 한 활동과 전체 건물을 구분. 직원의 발언 자체는 당사자 보고 |
| R4 | 접근과 운영 제약 반영 | recover · Gwanggyo stairs, Monday, last entry, route access | 광교 계단, 하이커 시간·마감 확인. 현장 전체 접근성 인증은 미실시 |
| R5 | 휴대폰에서 실행할 행동 하나를 확인 | ResultCard · 브라우저 desktop demo, strict goal, mobile whole-venue | 한국어 질문과 지도 검색 확인. 실제 직원 이해도는 미측정 |
| R6 | 복원·종료·수정 후 일관성 | session/RecoveryApp · 브라우저 reload/end, origin edit, undo | 화면 내 한 단계 취소. 늦은 응답 무시는 코드 대조, 집중 경합 측정은 미실시 |
| R7 | 영어 문장을 확인 후 반영 | interpret/SetupForm · 대역의 정상·모호·거절·장애, 브라우저 note needs confirmation | 실모델 필수·선호 분류율, 지연, 실제 청구 금액 미측정 |

규칙·모델 단위 시험 28개와 브라우저·HTTP 시험 7개가 수정 커밋의 GitHub Actions에서 통과했다. 같은 버전의 공개 배포 주소를 독립적으로 점검해 브라우저 시나리오 6건과 API 요청 8건의 예상 결과를 확인했다. 두 집계는 서로 다른 검증 환경의 기록이다. 채택 문구는 증거 수위를 맞춘다. 예컨대 ‘대기 45분을 입력하면 두 화면이 다르게 동작했다’는 재현 결과이고, ‘관광객의 결정 시간이 줄었다’는 실제 사용자에게 확인할 가설이다. ### 발견해 수정한 복귀 마감 경계

초기 버전 276204b에서 14:50에 ‘무대 필수·15:30 복귀·대기 40분’을 입력하면 처음에는 후보가 없었지만, 같은 보고를 두고 15:01에 평가하면 2층이 현장 확인 카드로 재등장했다. 수정 버전 4caabaab은 보고 시각에 대기를 더한 값이 복귀 마감과 같을 때도 체험 시간이 0분임을 먼저 판단해 제외를 유지한다. 새 대기를 5분으로 보고하면 이전 보고가 교체되어 현장 확인 상태로 돌아온다. CI에는 이 경계의 회귀시험을 넣었다. 공개 배포본에서도 최초 40분, 11분 경과한 동등 마감, 새 5분 보고 세 요청의 실제 응답을 검증했다.
