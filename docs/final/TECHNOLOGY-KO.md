# 기술 선택표

| 영역 | 선택 | 선택 이유 | 검토한 대안 | 채택하지 않은 이유 | 라이선스·조건 |
|---|---|---|---|---|---|
| 언어·화면 | TypeScript·React / 기본 CSS·Lucide | 화면·서버가 목표 타입을 공유한다. 두 화면을 한 곳에서 고친다. | Java/C 별도 서버, Tailwind·shadcn/ui | 별도 서버와 UI 부품을 함께 관리해야 한다. | TS Apache-2.0 / React MIT / Lucide ISC·일부 MIT |
| 서버 | Next.js·Node.js / Zod | 한 앱에서 입력 형식을 검사하고 시간·휴관을 계산한다. | 별도 API 서버·수동 검사 | 배포와 입력 검증을 두 곳에서 맞춰야 한다. | Next·Zod MIT / Node MIT·별도 고지 |
| AI 호출 | OpenAI Responses / GPT-6 Luna 후보 | 영어 메모를 목표·선호·접근 조건으로 읽고 사람이 승인한다. | 모든 단계에 대형 모델 호출 | 확정 조건을 계산할 때도 지연·비용이 발생한다. | 상용 API 약관·사용량 과금 |
| 데이터 | 출처를 붙인 JSON / 탭 세션 보관 | 세 활동의 근거를 직접 고치고 현장 대기 보고는 해당 탭에만 둔다. | TourAPI 전역 검색·중앙 DB | 목표 구역의 현재 대기 확인과 추가 운영이 필요하다. | 직접 작성 카드 / 원출처 이용조건 |
| 장소 열기 | Google Maps 위치 검색 링크 | 후보가 없으면 키 없이 약속 장소의 지도 검색을 연다. | 지도 SDK·경로 API | 별도 키·동선 데이터와 실제 소요시간 검증이 필요하다. | 외부 링크·서비스 약관 |
| 개발 도구 | Codex 한 세션 / 사용자 직접 지시 | 승민이 모델·작업 단위·변경 승인 시점을 선택한다. | Paseo 다중 세션 | 이번 팀에는 동시 작업 검토 비용이 크다. 선택 도구로 둔다. | Codex·Paseo 본체 Apache-2.0 / 서비스 별도 |
| 테스트 | Node 내장 시험 / Playwright | 규칙의 시간 경계와 휴대폰 화면 흐름을 재현한다. | Vitest 추가·수동 시연만 실시 | 규칙 시험은 내장 도구로 충분하고 화면 회귀도 확인해야 한다. | Node MIT·별도 고지 / Playwright Apache-2.0 |
| CI | GitHub Actions | 변경 시 시험·빌드·타입 검사와 SBOM 생성을 반복한다. | 개발자 PC에서만 실행 | 팀원별 검수 환경과 결과가 달라질 수 있다. | 호스팅 약관 / 사용한 액션 MIT |
| 배포·CD | Vercel / Git 연동은 본선 제안 | 화면·서버 버전을 함께 배포한다. 재단 계정으로 이관한다. | 직접 서버 운영·배포 | 한정 시간에 서버·복구 절차까지 운영해야 한다. | 호스팅 약관·플랜 한도 |

- 실모델 정확도·지연·비용은 미측정이다. 키 미설정, HTTPS 연결 실패, 빈 응답은 목표 버튼으로 복구한다.
- 잠금파일 SBOM 65개 중 14개 플랫폼 선택 항목에 LGPL 표기가 있다. 본선 배포물과 재단 인수 기준을 대조한다.
- 공식 링크·버전·라이선스 전문은 GitHub의 docs/SOURCES.md, package-lock.json, public/third-party.txt에서 확인한다.
